# 让自动切片接近人工剪辑：当前差距与实施路线

更新：2026-10-25。本文件是设计方案，新增能力尚未实现。

## 当前判断的依据

本次阅读了选片、渲染、字幕和封面代码，以及 `ouput/2026-10-21/analysis.json` 中的 8 条新切片记录；核对了部分原始字幕，并抽查“跟 AI 说谢谢”片段的 8 张原视频画面。没有逐条完整听看这 8 个成片，因此不报告总体准确率、观众留存或与人工剪辑的相似度。

这批输出状态为 complete，说明流程执行完成，不代表事件解释、节奏和封面均经过人工认可。旧批次 `ouput/new-batch-20261024` 的文案使用过 local_review 覆盖，不能用那些人工复核后的结果证明自动文案已经达到相同水平。

| 环节 | 现有能力 | 接近人工还缺少什么 |
| --- | --- | --- |
| 选片 | 字幕窗口发现候选、引文校验、触发与结果、文本边界复核、时间去重 | 读弹幕与本人自述的区分、画面事实、跨候选比较与取舍 |
| 边界 | 字幕起点前 200ms、终点后 500ms，并避开相邻字幕 | 根据实际发声、动作完成和笑声收尾调整 |
| 剪辑 | 每条截取一个连续时间区间 | 删除事件内部旁支、保留铺垫与反应、按需要组合多个原片段 |
| 字幕 | 词典纠错、真实时间戳、换行、显示纠错 | 按语义短句上屏、关键台词的二次识别与复核 |
| 封面 | 原视频取帧、文字模板、人工构图覆盖 | 自动核验表情与动作、角色位置、遮挡及缩略图可读性 |
| 验收 | 引文、时间、文件和编码等程序检查 | 渲染后的内容回看，以及用未参与调参的录播检验质量 |

代码位置：`core/highlight_selection.py`、`core/highlight_render.py`、`core/clip_editorial.py`、`core/clip_publication.py`、`audit_clips.py`。

## 先用实际问题定义目标

### “引用正确”之后，还需要确认“理解正确”

“跟 AI 说谢谢”片段为原视频 00:13:03.240–00:15:37.859。选片分析的 payoff 写着“主播承认自己也会说谢谢”，但字幕中同时有：

- ID 197：“我不跟ai说谢谢”。
- ID 202–204：“……那我 / 也有我也有我也说我也说你们说不说 / 我是为了鼓励ai哦”。
- ID 220–221：“我可以理解这样子的行为但是小然身上确实没有这样子的 / 情况出现过……”。

这里可能存在读弹幕、代入观众发言、表演或者其他上下文。没有核实原音和归属，就不能把“我也说”确定为主播本人习惯，更不能据此包装成“自打脸”。抽帧中能看到话题卡和弹幕，但静态画面本身也不能裁定语气。

因此，应新增“本人陈述 / 读弹幕 / 引用他人 / 表演 / 唱歌 / 不确定”的话语属性。只做说话人分离无法解决同一个人读弹幕的问题。遇到归属冲突，应保留疑点、使用中性描述或交给复核。

### “边界完整”之后，还需要决定“里面怎么剪”

当前 FFmpeg 渲染只有一组起点和时长，不能去掉中间旁支。此前收糖片段的审查记录指出，拒收与口袋反差之间夹有约 33 秒音乐、舞种和地板讨论；这是适合验证内部重剪的案例，具体删除范围仍应回看原音画确定。

相反，没字幕的几秒可能是表情、镜头调整或者等观众反应。不能按“静音超过阈值”一律删除。新的 154.619 秒 AI 话题也不应仅因为长就强行压成一分钟。

## 推荐的处理流程

录播 → 转写与语义分句 → 多路发现候选 → 事件事实复核 → 候选比较 → 剪辑清单 → 低清预览与检查 → 正式渲染 → 标题封面 → 成片验收。

### 优先级一：建立统一的事件事实记录

每个候选记录话题、人物、动作对象、铺垫、触发、反应、结果，以及它们对应的字幕 ID、原片时间和画面证据。选片理由、标题、封面共用这份记录，减少三个阶段各自发挥造成的矛盾。

建议增加：

- `speech_act`：本人陈述、读弹幕等属性；允许 unknown。
- `claims`：每项事件判断及支持、冲突的证据。
- `must_keep_ranges`：理解笑点必需的原片范围。
- `uncertainties`：专名、语音、指代或画面疑点。
- `review_status`：已核验、待复核或拒绝；不能把模型自评分当准确率。

保留原始 ASR、纠正文本与修改依据。只对候选中的关键笑点、专名、两模型有分歧的短音频补做第二次识别；两个识别结果一致仍不等于真值。口误、重复、拟声词可能就是笑点，不应被语言模型自动改成流畅书面语。

### 优先级二：增加有时间依据的视觉复核

本机继续用 FireRed 转写；在硅基流动另设视觉模型配置，传入候选画面与带时间的字幕。可以以 Qwen3-VL 系列作为待评测选项，具体型号由账户当时可用的模型列表确定。

建议分两层取样：候选全段先稀疏抽帧；疑似动作、表情和爆点附近再加密。抽样密度属于需要验证的参数，短暂反应可能被稀疏抽帧漏掉。视觉模型应返回“看到了什么、在哪张图、还有什么不确定”，不能只输出“很好笑”。

文字候选之外，再通过音频变化和低频画面扫描补充候选，减少漏掉纯表情、动作和无台词笑点的情况。音量突增只提示值得检查，不代表高光；直播画面长期不切镜，也不能单靠场景切换发现高光。

注意：视觉模型分析抽帧不等于听到了语气；本地 ASR 也不等于识别了反讽。归属仍有疑点的关键片段，应进入复核，或选择不依赖该推断的剪法与文案。

硅基流动官方已说明图片 URL/base64 的视觉请求方式。先验证候选图片请求和费用，再考虑整段视频接口，不把模型自身支持视频等同于当前网关支持所有视频输入格式。

### 优先级三：让剪辑计划支持多个原片段

新增可审阅的剪辑清单，每段包含原片范围、保留目的和删除依据。例如：

```json
{
  "event_id": "example",
  "segments": [
    {"source_start_ms": 10000, "source_end_ms": 18000, "purpose": "交代前提"},
    {"source_start_ms": 26000, "source_end_ms": 42000, "purpose": "反差与完整回应"}
  ],
  "removed": [
    {"source_start_ms": 18000, "source_end_ms": 26000, "reason": "已复核的无关旁支"}
  ]
}
```

上面的时间仅用于说明结构，不是当前视频的剪辑指令。

初版保持原片顺序，优先删明确无关的旁支，不重排因果、不拼接成主播没说过的话。模型提出语义范围，程序再依据词时间、发声与画面确定安全切点。

实现时必须同时处理音频、视频、字幕和时间映射。原字幕扣掉第一个起点的方法不再适用：删除中间一段后，后续字幕、重点台词和画面标记都需要映射到新时间轴；被删除范围内的文案证据也不能继续用于标题封面。

FFmpeg 的 trim/atrim、setpts/asetpts、concat 可以承担底层裁切和拼接。人声检测可以辅助找切点，但不能决定一段画面是否值得保留。先输出低清预览，检查接缝、语义和笑声，再生成正式成片。

### 优先级四：按个人风格控制节奏与包装

把用户偏好写成可执行的编辑规则，并从参考切片中人工标出几个“为什么这样剪”的正反例。关注铺垫长度、反应停留、何时结束和哪些背景知识需要交代；只模仿字体和封面排版不足以学到剪法。

当前字幕偏好继续保留：文悦新青年体、较大字号、统一黄色、无额外彩色强调。下一步重点是根据真实词时间按语义短句上屏，避免一屏提前暴露尚未说出的笑点、把称呼拆开，或在同一条字幕中混入下一个话题。

片内放大、补充弹幕、音效和转场均须有明确用途。停顿可能承担喜剧节奏，口误可能需要保留；不预设每隔几秒加效果，也不强制所有片段采用相同长度。

标题和封面在剪辑锁定后生成。标题只承诺成片里确实能兑现的看点；封面从已核验反应附近的候选画面中选，检查角色位置、表情、文字遮挡与 320px 缩略图可读性。虚拟形象检测效果需要实测，不能默认真人脸检测器可靠。

### 优先级五：用人工反馈决定是否真的变好

先标注约 20–30 个好与不好的事件，包含读弹幕误判、语音歧义、纯画面笑点、旁支过长和边界缺失。按整场录播划分开发集与验证集，避免同一段素材同时参与改提示词和验收。

对比当前版本、新版本与人工版本，随机顺序评看，记录：

- 前几条推荐中，真正愿意发布的比例；允许少出片，不强行凑满配置上限。
- 关键台词是否听错，事件对象与话语归属是否正确。
- 是否缺铺垫、半句进出、笑声或动作尚未结束就切走。
- 哪些秒数可以删，哪些删掉后破坏了笑点。
- 每条还需人工修改多少分钟，以及每小时录播的处理时间与费用。

若要测漏掉了多少高光，必须对整场录播标注；仅检查输出的 8 条无法计算召回率。开发者的结构测试和模型自评分也不能替代这些观感指标。

## 下一次实施建议

第一轮先交付“事件归属复核 + 多段剪辑清单 + 预览验收”，用三类素材做前后对比：本次 AI 谢谢话题、此前收糖旁支、一个依赖动作或表情的片段。先确认事实不被误解、内部删减确实更顺，再扩大自动处理范围。

第一阶段的目标是稳定产出可发布的草稿，并把少数疑点集中给人处理。只有在不同录播的人工对比中持续改善，才有依据宣称接近人工剪辑。暂不需要训练一个新大模型。

## 技术依据

- [Qwen3-VL 官方项目](https://github.com/QwenLM/Qwen3-VL)：视觉、OCR、视频理解和时间定位能力；不能由此推导对本项目每个笑点的准确率。
- [硅基流动视觉理解文档](https://docs.siliconflow.cn/docs/userguide/capabilities/vision)：图片 URL 与 base64 请求格式。
- [硅基流动 Qwen3-VL 上线说明](https://www.siliconflow.com/blog/qwen3-vl-on-siliconflow-next-gen-vlm-with-better-world-understanding)：平台曾提供的系列型号；当前账户可用性需在接入时确认。
- [Silero VAD 官方项目](https://github.com/snakers4/silero-vad)：本地人声活动时间检测，可用于辅助边界。
- [FFmpeg 滤镜官方文档](https://ffmpeg.org/ffmpeg-filters.html#concat)：多段音视频拼接及时间戳要求。
- [FireRedASR2S 官方项目](https://github.com/FireRedTeam/FireRedASR2S)：现有 ASR 家族与语音处理能力说明。
