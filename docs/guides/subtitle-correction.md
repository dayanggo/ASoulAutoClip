# 在内容分析前修正已知转写错误

当前 `run_clips.cmd` / `analyze_recording.py` 入口默认读取 `resources/dictionaries/asr_dict.txt`。旧的纠错器原先仅在旧入口使用，新的录播选片流程此前没有接入它。

现在的顺序是：

原始视频 → 本地 ASR 或已有 SRT → 词典纠错 → 选片和边界复核 → 投稿标题、封面文案 → 烧录字幕。

词典修正会同时影响模型的理解和最终字幕，不只是把错字在导出视频时换掉。正文中的文字会改变，但字幕 ID、起止毫秒和原始 ASR 文件保持不变。词级原始时间不会被伪装成已重新对齐。

## 如何使用

编辑 `resources/dictionaries/asr_dict.txt`，每行 `错误写法 正确写法`，中间用空格或 Tab；空行和以 `#` 开头的行会跳过。含空格的词组可用 `_` 表示空格，与原词典格式兼容。例如：

```text
佳然 嘉然
夹心糖 嘉心糖
嘉兴糖 嘉心糖
冉冉 然然
asoul A-SOUL
```

先看纠错结果、不调用选片 API：

```powershell
.\run_clips.cmd --prepare-only
```

已有有效 ASR 缓存时会直接复用；没有缓存时仍会先进行本地转写。随后打开输出目录 `corrections.html`，逐条查看原始文本、修正文本和命中规则。

正式按修正后的字幕重新理解内容和出片：

```powershell
.\run_clips.cmd
```

无需删除 ASR 或 API 缓存。修改词典会重新计算纠错；选片和投稿编辑按实际输入文本复用或更新缓存。重新选片可能产生新的片段 ID 和输出目录，投稿清单只列本次结果。已经烧进旧 MP4 的错字需要重新编码才能改正。

`--restyle` 复用已有选片，`--package-only` 复用已有成片，都不能替代重新选片。如果先准备了新字幕，旧分析仍基于另一版字幕，`--restyle` 会提示直接运行完整流程，避免混用证据。

## 配置与容易误改的规则

默认配置：

```json
"correction": {
  "enabled": true,
  "dictionary_path": "resources/dictionaries/asr_dict.txt",
  "ignore_sources": []
}
```

相对路径以项目根目录为基准。`ignore_sources` 是暂不执行的左列原词，`enabled=false` 可关闭本阶段。指定的词典缺失、格式有误或同一左列对应两个不同右列时，会明确报错，不会悄悄跳过。

词典不是语义判断。例如当前词典里的 `背景 北京` 会把“背景板”变成“北京板”，`检查 检察` 会把“检查一下”变成“检察一下”。本次已将这两个原词加入本机 `config/local/highlights.json` 的 `correction.ignore_sources`，原词典未改动：

```json
"ignore_sources": ["背景", "检查"]
```

像 `必须 必需`、`权力 权利` 等规则也依赖语境；如果明细中出现误改，可以加入忽略列表，或把原规则缩小到已核对的具体短语。不要把所有同音词都当成全局替换规则。

程序优先匹配长词，同一份原文只替换一遍。例如 `北京图 背景图` 和 `背景 北京` 同时存在时，原文“北京图”会得到“背景图”，不会又被替换成“北京图”。每次重跑都从原始字幕开始，不对上一轮修正结果连续套规则。英文词会检查边界，`ace` 不会改动 `space`。

只替换字幕正文，不能对 SRT 文件全文直接执行词典替换：现有 `. 点` 规则会破坏使用点号的时间码，原来的全文替换方法不适合新流程。

## 输出与核验范围

- `corrections.html`：可阅读的前后对照和规则明细。
- `corrections.json`：本次词典指纹、忽略规则、修改统计和逐条变更。
- `correction/<指纹>/transcript.corrected.srt`：分析和渲染使用的字幕。
- `correction/<指纹>/changes.json`：本版本变更记录。
- `asr/.../transcript.srt` 和 `transcript.words.json`：保留原始识别结果。

词典只能处理已收录的固定错法，当前按每条字幕正文匹配。跨字幕词组、漏字、错听整句等问题仍可能存在。应听原音确认后添加精确规则或手动修正 SRT；不要让文本模型自由改写整段后，把改写内容视为原话证据。即使字典里写了“错误→正确”，也不等于能自动证明每一次命中都适用。
