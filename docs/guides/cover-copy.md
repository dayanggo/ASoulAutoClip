# 封面文案完整性修复

2026-10-25，用户指出 ASMR 切片封面的“ASMR道具声像什么？／确实也像”读不通。

原因是原逻辑主要验证字幕引用、长度和部分无证据描述，没有单独检查整张封面脱离上下文后能否成立。这里“确实也像”确实出现在字幕 329，却没有在封面上说明像什么；标题还补出了未由字幕证明的“点头”。与此同时，关闭投稿编辑时的旧兜底会截取证据前 12 字，也可能造成半句话。

## 新流程

1. 初稿模型先生成完整、通顺的 `cover_text`，再按语义拆为 `cover_lines`。分行后的文字去掉标点空白，必须与完整文案相同；不允许为了排版删字截句。
2. `core/cover_copy.py` 检查长度、分行一致性及少量明显的残句。两行可以合为一句，不要求每行独立成句。例如“像心跳吗？／确实很像”有明确对象，可以通过；“像什么？／确实也像”缺少对象，会要求重写。
3. 默认通过已有模型 API 追加独立审校请求，输入完整片内字幕和初稿，检查通顺性、具体指代、事实、说话人和无证据动作，输出最终文案。原话不适合封面时可改为有证据的 `caption`，不能给 `quote` 擅自补字。
4. 最终文案再经相同的引文、ID、长度及完整性检查。审校只允许改标题和封面，程序保留初稿的取帧与字幕重点标注。
5. 初稿与最终结果分开缓存。审校遇到额度/网络失败，不丢掉有效初稿；重跑可以只请求审校。审校版本和提示词参与缓存身份，旧的未审校结果不会冒充已审校缓存。

通常每条新切片的投稿文案阶段需要两次模型请求：初稿一次、审校一次；各阶段最多两次校验尝试，HTTP 重试另计。配置 `publication.copy_review_enabled=false` 可关闭额外请求，基础程序检查仍启用。有效本地 `editorial.overrides.json` 按本地复核处理，不调用生成或审校 API。

`generate_publication` 在使用缓存和截图前也检查文案，避免 `--package-only` 绕过明显残句检查；失败保留已有封面。无编辑结果时改用完整选片标题按词分行，拒绝超长标题，不再任意截取证据前 12 字。

这些检查不能保证所有中文句子自然，也不能仅凭字幕判断画面和真实情绪。同一个模型的独立审校仍可能漏错；`copy_review.method=independent_model_pass` 只记录处理方式，不代表人工审核或准确率证明。
