# 看点门槛与弃选规则

之前的 `score` 只用于排序，没有最低通过分。证据和时长合规、事件前因后果完整的普通问答，也可能排进前几名。现在把内容价值与事件完整性分别判断。

## 默认行为

- `selection.min_score=85`，初选分低于门槛时直接弃选，不进入后续复核、文案或编码。
- 现有边界复核请求同时输出 `quality_review.score` 和 `quality_review.reason`，评估修正后整个连续区间的具体看点、重复和无关旁支。没有额外增加独立的一轮请求。
- 复核不接收初选分数、初选推荐理由或数值门槛，减少跟随原分数以及迎合通过线的倾向。
- 最终分取 `min(初选分, 复核分)`。任意一轮不够分就正常弃选，不报成任务失败，不请求模型反复抬分。
- `max_clips` 只是上限。只找到一条就出一条，一条都没有也可成功完成并输出报告。
- 默认受众为不了解主播的普通观众；只有粉丝背景才成立的看点不自动进入高分区。独立弹幕的“绷”可提示回看，并给通过两轮质量检查的候选增加排序权重，不改变原看点分，详见[大众向与弹幕加权](audience-and-danmaku.md)。
- 缺少分数、畸形复核结果、伪造引文、网络错误仍按原规则校验或记录失败，不会当作质量弃选掩盖。

## 评分标尺

两阶段提示词使用相同标尺。分数属于模型的编辑判断，尚未通过人工标注集校准，不是观众满意率或准确率。

| 分数 | 内容判断 |
| --- | --- |
| 0–39 | 日常操作、流程或没有独立看点 |
| 40–59 | 普通闲聊问答，结果平淡 |
| 60–79 | 略有趣但常见、结果可预期、依赖粉丝背景才成立，或少量亮点被大量重复及无关内容稀释 |
| 80–89 | 陌生观众也能理解，有原文支持、具有辨识度的包袱、意外回应、有趣互动或有吸引力的完整故事 |
| 90–100 | 陌生观众无需补课，少见且突出的强看点或连续递进，证据充分 |

事件完整不自动加分。游戏直播的普通死亡重试、讲按键、读任务、加载等待和反复抱怨，不因主播说了话就视为高光。单个好梗可以通过，必要铺垫不算拖沓，不按每分钟梗数硬切，也不为提高分数删掉前因和收尾。纯画面操作仍无法仅从字幕可靠判断。

## 使用

配置中可显式填写：

```json
"selection": {
  "min_score": 85
}
```

将该字段合并到原有 `selection` 对象，不要删除其他设置。当前示例、本地默认和三人电台配置均已设置为 85；旧配置省略该字段也会继承 85。

也可以在原完整启动命令后追加参数，覆盖本次门槛：

```bat
--min-score 90 --analyze-only
```

先看报告再去掉 `--analyze-only` 生成视频。85 是本次设定的初始值，90 更严格，80 更宽松；应按你人工看过的结果调整，不能保证某个分数必然好笑。取值范围为 0–100 的整数。

如果希望审阅轻度趣味的素材，可在单场配置中把门槛降至75，保留真实评分、原文证据和完整性校验，先用报告回看。75属于更宽松的编辑取舍，不代表片段更准确或必然适合大众；不需要因此修改公共默认值，也不要让模型为了达标抬分。

`--min-score` 不回写配置；两次命令若希望使用同一非默认门槛，都要保留它。该参数不能搭配 `--package-only`、`--restyle`、`--captions-only` 或 `--prepare-only`，这些模式不会重新选片。

继续用同一视频和输出目录可以复用有效转写。这次提示词改变后，第一次重跑需要重新请求选片和复核；以后仅改变门槛，已有有效评分会直接复用，不为调整分数重新调用接口。新放行且此前没做过复核的候选，仍需复核请求；首次生成文案和视频也按原流程执行。

零产出时先区分两种情况：`rejected` 有 `stage=quality` 的记录，说明确有候选被分数门槛拦下；若各窗口的模型响应本身都是 `clips: []`，而 `rejected` 也为空，则模型在发现阶段就没有提名。只降低 `min_score` 不会把空响应变成候选，重跑还会复用对应缓存。此时可针对单场调整 `selection.brief` 的候选偏好，例如允许有具体语境、完整起因和回应的轻度趣味、自嘲或小反差，并要求如实给分；偏好变化会使对应初选缓存失效，ASR仍可复用。纯画面事件不能用这种方式假装已经看过，允许零产出的规则继续保留。

旧的 `clips/` 文件夹不会自动清除，避免误删已审阅的成片。新的报告和投稿清单只列本次通过的片段，应以它们为准，不能把文件夹里所有历史 MP4 当成本次产量。

## 核查本次结果

- `analysis.json` 的 `quality_policy`：本次门槛与取分规则。
- 每条通过切片的 `selection_score`、`quality_review`、`score`：初选分、复核分及理由、最终分。
- `rejected` 中 `stage=quality`：被挡下的候选、阶段、分数和原因。
- `report.html`：门槛、通过片段的两轮分数与理由、弃选记录。允许显示通过 0 条。

对应测试见 `tests/test_highlight_quality.py`，验证门槛拦截、复核降分、缓存、畸形输出、证据校验、报告和零片段时不编码等行为。测试不调用真实付费模型；过滤机制通过不等于真实素材的审美质量已经验证。
