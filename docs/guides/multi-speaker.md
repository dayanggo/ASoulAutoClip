# 三人电台切片：准确性改进

日期：2026-10-26。本场录播为 2026-10-25《线下结束后的三人电台》，用户确认参与者为嘉然、贝拉、乃琳。

## 当前能力与问题

当前 `Subtitle` 只包含 ID、时间和文本，FireRed 转写结果没有经过说话人分离。模型能参考上下文理解接话，但没有可靠的逐句身份标签。字幕 ID 不等于说话轮次，一条 ASR 字幕也可能混入两人发言；名字出现可能是在称呼或转述，不能证明是她本人在说。

因此，三人电台需要分别检查转写内容、发言归属、完整对话边界和标题封面的解释。只增加模型请求或让文案更通顺，不能修复原始字幕中的归属错误。

## 这次已准备的低成本调整

专用配置：`config/local/radio.json`。它继承现有本地 ASR、硅基流动 API 配置和字幕样式，使用本场录播及 `ouput/2026-10-25-radio` 输出目录。没有启动实际录播转写、API 分析或渲染。

| 项目 | 本场配置 | 用途与限制 |
| --- | --- | --- |
| 录播背景 | 嘉然、贝拉、乃琳；常用称呼；发言身份未确认 | 帮助理解话题与提及对象，不冒充声纹识别 |
| 边界复核上下文 | 前后各 60 秒 | 给模型更多问题和补充回应；只是分析范围，不会固定给切片加一分钟 |
| 允许最大时长 | 240 秒 | 避免完整多人互动因 180 秒上限被放弃；仍不能包含较长无关旁支 |
| 分窗重叠 | 240 秒 | 与本场最长目标片长配套，降低窗口交界处丢失上下文的机会；高密度字幕还受字符预算限制 |
| 最大成片数 | 5 条 | 减少第一批复核量；减少数量本身不等于提升准确率 |
| 前后缓冲 | 300 / 800 毫秒 | 仅在相邻字幕约束允许时留少量余量，不解决叠音或错误词时间 |
| 文案审校 | 开启 | 检查通顺性与无证据归属；仍是基于文字的审校 |

这些是针对多人电台的起始参数，没有用本场真实素材做前后准确率对照。600 秒窗口和原有字符预算保持；背景会进入选片、边界复核、投稿初稿和文案审校各阶段。

提示词新增多人对话规则：区分被提到的人、发言者、被回应者、转述和读弹幕；不把两人的问答写成一人改口；指代不清需回看必要前文；同一事件中其他人的纠正与补充不能因为首位说话人结束就被裁掉。笑点依赖无法确认的具体身份时允许弃选。

投稿编辑原来只从文件名提取允许提及的成员名，这场文件名没有成员姓名。现在会同时读取用户背景和片内字幕中的成员名，并明确发送 `speaker_attribution=unavailable`。名单仅允许谈及相关人物，不证明台词归属；背景变化会使对应投稿编辑缓存失效。

## 使用方式

CMD 中运行以下命令；它会实际开始处理，本文档不会替用户执行：

```bat
cd /d E:\pyProject\ASoulAutoClip
.\run_clips.cmd --config ".\config\highlights.radio.local.json"
```

若先检查选片、暂不出片，可以在同一命令后加 `--analyze-only`。随后去掉该选项重跑，复用有效转写和选片缓存。报告为 `ouput/2026-10-25-radio/report.html`。

专用配置从本地配置复制，后续若修改了密钥环境变量名称、API 模型或 ASR 配置，也应同步检查这份文件。密钥仍由原来的环境变量或 `.env` 提供，不需要发到聊天里。

## 下一项实质升级：说话人时间轴

推荐先试用本地 [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)。官方支持已知人数约束、GPU、本地离线运行和便于合并转写时间的 exclusive diarization。模型文件下载需按其说明接受访问条件并配置 Hugging Face token。另可评估中文语音方向的 [3D-Speaker](https://github.com/modelscope/3D-Speaker)，提供 CAM++、ERes2Net 和说话人分离流程。不能把不同项目、不同年代的测试集结果直接当作本场三人电台的效果排名。

建议的数据链路是：保留现有转写与真实词时间 → 音频说话人时间轴 → 用人工确认的清晰片段映射真实姓名 → 按词时间关联字幕 → 带角色和不确定性选片与复核。A/B/C 标签本身不代表嘉然/贝拉/乃琳；换片段单独聚类时还可能重新编号，必须重新匹配或使用统一的参考映射。

只有确定音频中确实只有三位发言者时才固定人数为三；存在回放、访客或其他人声时应允许人数范围。多人同时说话的区间要保留重叠或不确定标记，不能强制给一个人；exclusive 结果适合关联时间，但不应据此抹掉真实叠音。还原重叠人声需要额外处理，单纯分离标签不能保证转写正确。

该模块本轮没有接入，也没有下载模型。4060 的具体速度和显存需求需要短音频实测；若后续接入，建议独立环境、分阶段运行，先卸载 ASR 再运行分离模型。

## 如何验证有没有改善

用同一场录播比较原配置和专用配置，抽查候选的三个方面：内容是否确有看点且没有曲解、发言归属是否有依据、必要问题和最后回应是否完整。没有确认身份时保守描述，不把未知算成正确识别人名。合格候选比例可以人工统计；漏选率需要另外标注录播中应当保留的事件，不能仅凭已导出的几条估算。

模型的 `score` 是排序依据，不是准确率。增加上下文、名字背景和文字审校只能降低部分误解风险，效果必须由实际素材对照确认。
