# 当前 7 条切片的准确性审查

检查时间：2026-10-18。检查范围是当前 `ouput/analysis.json` 指向的 7 条成片；不是重新选片后的结果。依据包括全部片内字幕、相邻上下文、关键帧抽查、真实 FFmpeg 媒体检查、原始 FireRed 日志及本机 Whisper large-v3 对 4 段高风险素材的独立转写。未进行逐句人工听写，不能给出严谨的 WER/CER 或总体准确率。

本次没有调用付费选片 API，没有覆盖原来的 7 条视频。可回看的报告在 `ouput/audit/report.html`；JSON 保存结构检查、字幕差异和时间复核，报告附有独立识别结果及对应原音，便于人工复核。

## 已确认的问题

### 1. 旧 FireRed 字／词时间戳实际上退回了均分估计

`ouput/asr/bf963f52099369bc/asr-cuda-error.log` 中出现 436 次 `log_probs must be float64, float32 or float16 (half) type`，与本次 436 个语音分段数量一致。模型以 bfloat16 推理，但 torchaudio 强制对齐接口不接受此类型；上游捕获异常后返回空对齐，再在 `_get_and_fix_timestamp` 中按文字数量平均分配时长。

其中 347 个至少包含 4 个 token 的分段直接呈现均分特征，其余短段和英文词合并后不适合用这一特征判断。之前仅检查“有 timestamp 字段”和时间单调，没能识别上游的估计降级。此处需要纠正此前对时间戳可靠性的判断。

本轮已修复：

- 只将 CTC 输出转换为 float32，主模型保留 bfloat16，避免增加整模型显存。
- 对齐失败就明确报错，不再接受平均分配时间戳；保留实际 CTC token 之间的停顿。
- 新 FireRed 缓存与旧版本隔离，旧估计时间不会冒充修复结果。
- 保留原始识别文字，对全部 436 段重新执行 CTC 对齐；全部完成，写入 `ouput/asr/a54ea03b19f621de/`，生成 515 条字幕。新旧原始识别文字逐段相同。
- 另外用真实 6 秒语音完成修复后的完整 FireRed GPU 转写，验证新解码路径也可正常对齐。

在旧 7 条切片内、能够按同一 token 对照的 1410 个词／字中，有 240 个起点相对修复后的 CTC 时间变化超过 0.5 秒，61 个超过 1 秒，最大约 2.48 秒。这是两个版本之间的对齐差异，不能当作人工标注误差率。

这 7 条所选起止词本身的差异相对小：起点约 100–300 毫秒，末词结束约 35–407 毫秒。不能由此宣称每条视频都已截断人声；更直接的问题是部分内部字幕与台词可能错位，以及机械分句影响语义边界选择。

### 2. 正文纠错尚未应用到旧成片

当前分析和已烧录字幕仍基于原始 ASR。按当前词典配置对照，女仆片段有 2 条、拉扯片段有 2 条字幕与修正文本不同。整场已得到的“15 条、17 处替换”不代表旧 MP4 已更新。

词典还没覆盖“主营、主游、黄金国宝有、i’m maya”等可疑内容。Whisper 抽查也把“锅包肉”识别成近音词，因此不能简单换一个 ASR 后就认为文字准确。应优先听核笑点、专名和两套模型分歧的语音。

### 3. 引文真实存在，不代表事件解释正确

14 条选片证据均能匹配分析所用字幕，且都落在所选区间内。7 个视频的时长与计划差异为 0–30 毫秒，字幕文件与分析输入一致。这些结构检查通过。

但“番茄”片段的原画面拍品板写着“阿草”，前景也是持吉他的阿草；番茄是弹幕出价，原分析却解释为竞拍番茄物品。说明“quote 能找到”不足以验证拍品、出价、说话人和指代关系。

## 改进顺序

1. **先采用修复后的 CTC 对齐，再应用词典纠错并重分析。** 时间和文本是后续选片、字幕和文案的共同基础。本轮已完成对齐修复和缓存准备，旧片尚未重选或重编码。
2. **只对高风险候选补做第二遍识别与听核。** 优先覆盖关键证据、专名、异常英文、未知 token 和两个模型差异大的短段。保留差异，不让文本模型自由改写原话。
3. **把“引用校验”和“事件理解复核”分开。** 新增拍品、出价、读弹幕还是本人发言、指代对象等结构字段；对依赖画面的候选取 3–5 帧视觉复核。当前文本模型不能仅靠字幕判断这些关系。
4. **改善语义分句和边界。** 当前按约 7 秒、28 字切字幕，可能把“我也想你们”和“昨天想发动态”放进同一条。应按句意边界关联真实词时间，再选完整的触发、反应和收尾。
5. **最后优化节奏。** “收糖”适合保留证据链的内部剪辑；海盗的无字幕间隔可能包含视觉笑点。静音检测、字幕空白和重复字数只能提示复核，不能自动决定删除。

FireRed 官方实现与时间戳能力说明：[FireRedASR2S](https://github.com/FireRedTeam/FireRedASR2S)。独立对齐的技术依据可参考 [WhisperX 论文](https://arxiv.org/abs/2303.00747)。强制对齐是把给定文字定位到音频，不能证明文字本身听对了。

## 使用

再次检查已有成片，不转写、不请求 API、不重新编码：

```powershell
.\.venv\Scripts\python.exe -X utf8 audit_clips.py
```

要基于修复后的字幕重新选片、出片：

```powershell
.\run_clips.cmd
```

当前配置会复用本轮修复后的 FireRed 缓存，无需重新下载或整场解码。选片 API 会按新字幕重新分析，原有片段可能被替换为新的候选、边界和 ID。旧的人工构图与文案复核按片段 ID 绑定，不会错误套用到新事件上。
